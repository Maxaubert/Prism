# A terminal in Prism

2026-08-20

Each tab gets one shell, docked to any edge of the viewer, living and dying with
its project. The sidebar, the viewers and folder paging all keep working around
it: the terminal is a panel inside a tab, not a mode.

## The line being crossed, stated once

Prism's product line so far is "Prism never runs anything": the open-with
handlers only launch executables main itself enumerated, and every write goes
through the Recycle Bin. A terminal executes by nature, and no root wall can
apply to it - a shell can `cd` anywhere and do anything the user can. That is
the point of it, and it was asked for explicitly (2026-08-20). The line that
remains: PRISM runs nothing on its own. It spawns a shell where the user asked,
shows it, and forwards keystrokes. No command is ever generated by the app.

## Decisions

| Question | Answer |
| --- | --- |
| Model | Per tab. One shell per tab, cwd starts at the tab's root |
| Count | Exactly one. Want another? Open another tab (the `+` allows duplicates) |
| Split | One panel docked to an edge of the viewer area: bottom, top, right or left. Resizable by dragging its inner edge |
| Dock choice | Right-click menu on the panel: Dock bottom / top / left / right. Remembered globally |
| Shell | pwsh if installed, else Windows PowerShell. Settings → General lists what the machine has (pwsh / powershell / cmd / WSL distros) to change the default. New shells only |
| Lifecycle | Hiding the panel keeps the shell running. `exit`, closing the tab, or quitting Prism kill it. No running-process warnings in v1 |
| Toggle | `Ctrl+`` ` and a button on the sidebar search row, right of the folder button, left of the search box. Accent-lit while the panel is open |
| Switching tabs | Shows that tab's terminal (if it has one open), scrollback intact. The shell never notices |

## Architecture

Three pieces, one per process layer, matching the app's existing shape.

### Main: the PTY host (`src/main/terminal.ts`)

Owns every live shell through `node-pty` (ConPTY on Windows). Sessions are keyed
by an id the renderer assigns - the same pattern as tabs, where the renderer
owns the list and main owns the resources.

IPC surface:

- `term:spawn(id, root, shell)` → spawns the shell with `cwd: root`. Refuses an
  id that is already live. The shell must come from the detected list (below):
  main never execs a renderer-supplied path, keeping the open-with rule that
  main only launches what main enumerated.
- `term:input(id, data)` → write-through to the pty.
- `term:resize(id, cols, rows)` → pty resize.
- `term:kill(id)` → dispose the pty.
- `term:shells()` → the detected shells, cached: pwsh, powershell, cmd, and one
  entry per WSL distro (`wsl.exe -d <name>`), each `{ id, name, exe, args }`.
- Events to the renderer: `term:data(id, chunk)` and `term:exit(id, code)`.

Output is batched per animation-frame-ish interval (~8ms flush) so a `type` of
a huge file does not send ten thousand tiny IPC messages. On `will-quit`, every
pty is killed.

`node-pty` is the app's first native module. electron-builder already runs
`@electron/rebuild` during packaging and the machine has the toolchain (VS 18,
node-gyp 12); proving that end-to-end is the plan's first task, with
`@lydell/node-pty` (same API, prebuilt binaries) as the named fallback if the
rebuild fights.

### Renderer: the terminal surface (`src/renderer/src/components/TerminalPanel.tsx`)

`@xterm/xterm` + `@xterm/addon-fit`, lazy-loaded exactly like CodeView so the
launch path never pays for it. One xterm `Terminal` instance per session, each
owning its own DOM element; switching tabs hides one element and shows another
rather than repainting, which is what keeps scrollback, selection and the
alternate screen (vim, htop) intact for free. The instances live in a module
store (`lib/termStore.ts`) keyed by session id, outside React, because their
lifetime is the shell's, not any component's.

Theme: xterm's colors come from Prism's existing tokens - near-black background,
the indigo accent for the cursor and selection. No configurable terminal themes.

### The layout (`App.tsx` + `components/TermDock.tsx`)

The viewer area becomes a flex container holding the viewer and the panel, with
`flex-direction` derived from the dock edge (column for bottom/top, row for
right/left) and order putting the panel on the chosen side. One drag handle on
the panel's inner edge, following Sidebar's drag pattern. Size is remembered per
axis (one height for bottom/top, one width for right/left) in localStorage,
like the sidebar width. Dock edge is global, also localStorage.

The panel renders inside the tab's content area, so the sidebar, the tab strip
and the title bar are untouched. Fullscreen hides it with the rest of the
chrome.

## Tab integration

`Tab` gains one field: `term: { id: string; open: boolean } | null`.

- Toggle with no session → assign an id, `term:spawn`, `open: true`.
- Toggle with a session → flip `open`. The shell runs on unseen.
- `term:exit` (typed `exit`, or the shell died) → session removed, panel closes,
  xterm instance disposed.
- Tab close → `term:kill` for its session. The dirty-file dialog is separate
  and unchanged; no process warnings in v1.
- Reroot (the sidebar folder button) → the shell keeps running with its old
  cwd. Killing a dev server because the tree moved would be worse; the panel is
  visibly the same shell, and `exit` + reopen gets the new cwd.
- Not persisted: `tabs.json` stays as it is. Shells die with the app, so a
  restored tab starts with no terminal.

## Focus and keys

xterm focuses a hidden textarea, so App's existing `typing` guard already keeps
folder-paging arrows, `Ctrl+B`, and the rest away from a focused terminal - the
same mechanism the search box uses, no new focus machinery.

- `Ctrl+`` ` toggles the panel. Opening focuses the shell; closing returns focus
  to the window. Works while the terminal is focused (App's listener runs in the
  capture phase; this is one of the few keys it claims over a focused terminal,
  along with `F11`).
- `Escape` belongs to the shell while the terminal is focused - vim and every
  TUI depend on it, so Prism must not intercept it there. The way OUT of the
  terminal is `Ctrl+`` ` (toggle, which blurs) or clicking elsewhere. This is a
  deliberate difference from documents, where Escape hands the keys back: a
  terminal is the one surface where Escape has a job of its own.
- Everything else goes to the shell, including Tab, arrows, Ctrl+C. Copy is
  Ctrl+C-with-selection / Ctrl+Shift+C, paste Ctrl+V (xterm's Windows-standard
  behaviour), right-click pastes when there is no selection, copies when there
  is - Windows Terminal's rule.

## AI CLIs are first-class

Claude Code (and its kind) is the primary workload this terminal is being built
for, and the places generic terminals fail it are known. Prism controls both
ends - xterm and the Electron clipboard - so it does not have to fail the same
ways.

**Image paste.** A pty carries text; an image can never travel through "paste".
Claude Code's image paste works by reading the OS clipboard itself when it sees
the Ctrl+V keystroke - so the terminal's whole job is to NOT swallow that
keystroke when there is an image to read. Prism's paste rule, decided by a pure
function over the clipboard's formats at the moment Ctrl+V lands:

1. Clipboard holds an **image** → forward the raw `^V` byte (0x16) to the pty.
   A clipboard-aware TUI (Claude Code) reads the image and attaches it; a plain
   prompt ignores it harmlessly (PSReadLine's own Ctrl+V paste is a text no-op
   when the clipboard has no text).
2. Clipboard holds **text** → xterm's normal bracketed paste. Multi-line text
   arrives as one paste event, which is exactly what keeps Claude Code from
   executing line one before you finished pasting line five.
3. Clipboard holds **copied files** (Explorer Ctrl+C) → paste the quoted
   path(s), space-separated. `claude` then reads the file by path - this also
   covers images when they were copied as files rather than as bitmaps.

Right-click keeps Windows Terminal's rule (copy selection, else paste) and runs
through the same decision.

**Drag and drop.** Dropping a file ONTO the terminal panel types its quoted
path instead of opening it in the viewer - the other way images (and any file)
get into an AI prompt. Drops anywhere else keep opening files; the panel stops
propagation.

**Rendering.** Truecolor on, `scrollback: 10000`, `@xterm/addon-unicode11` so
the emoji and CJK width math matches what Ink-based UIs assume (misaligned
spinners and boxes are the tell of a terminal without it), and
`@xterm/addon-web-links` so the URLs Claude Code prints are clickable.

**Shift+Enter.** Ink UIs want a newline-without-submit, and `/terminal-setup`
exists purely to teach terminals that. Prism maps Shift+Enter to backslash+CR
(`\\\r`) at the xterm layer - the continuation form Claude Code accepts
everywhere - so it works out of the box with nothing to run.

**The acceptance test is Claude Code itself**, installed on this machine: run
`claude` in a Prism terminal, paste a screenshot (Win+Shift+S then Ctrl+V),
confirm it attaches; paste multi-line text, confirm it stays one prompt;
Shift+Enter, confirm a newline not a submit.

## Settings

Settings → General gains a "Terminal shell" dropdown fed by `term:shells()`.
Stored in localStorage; applied to the next spawned shell. A saved shell that no
longer exists on this machine falls back to the pwsh/powershell default without
comment.

## Errors

- Spawn fails (shell missing, ConPTY error) → the panel shows one line in the
  terminal's own style - `Could not start pwsh: <reason>` - and a Retry link.
  No dialog.
- The pty dies unexpectedly → same as `exit`: panel closes, session gone.
- IPC data for a session the renderer no longer knows → dropped silently
  (a race on tab close, not a bug).

## Testing

- Pure logic, unit tested: shell detection parsing (`wsl -l -q` output, the
  pwsh/powershell/cmd probe), the session-registry bookkeeping in
  `termStore.ts`, and the panel-layout derivation (edge → flex direction/order,
  size clamping).
- e2e (`terminalScenario`): toggle the panel, type `echo prism-e2e-marker`,
  assert the marker renders in the xterm DOM; hide the panel, run a background
  `Start-Sleep`-free check (echo a second marker after re-showing) to prove the
  shell survived hiding; `exit` and assert the panel closed; close the tab with
  a terminal open and assert nothing hangs. Runs the real pwsh - it is on the
  machine and in CI there is none, but e2e is local-only today anyway.
- Packaging: the standing install step now also proves the native module - the
  installed app must open a terminal, which fails loudly if node-pty was not
  rebuilt into the asar unpacked area correctly.

## Out of scope (v1)

Multiple shells per tab, split terminals, process-running warnings on close,
persistence of shells or panel state across restarts, configurable terminal
themes/fonts, search in scrollback, tasks/automation of any kind. The dock edge
and size are the only layout freedoms.
